# Context Router

## 1. 作用

在每个任务段开始时判断场景，决定只加载哪些执行上下文。路由不是任务分类标签，而是行为选择依据。

必须同时考虑：

1. 用户本次意图；
2. 目标事项当前状态与 handoff；
3. 需要产生的交付物；
4. 风险与外部副作用；
5. 当前是否发生模式切换或上下文恢复。

## 2. 模式

### `coding`

加载 `contexts/coding.md`，当工作主要是：

- 实现、修改、修复、重构代码或脚本；
- 编写测试、运行测试；
- 构建自动化、工具或配置；
- 创建结构性产物，且结果需要用工程方式验证。

### `review`

加载 `contexts/codex-review.md`，当工作主要是：

- Codex 独立审查代码、文档、计划或交付物；
- 独立核验是否正确、完整、可复现；
- 风险评估、回归检查、差异比较；
- 用户要求“看看有没有问题”“确认是否完成”。

### `delegation`

加载 `contexts/delegation.md`，当工作主要是：

- 把实现任务交给 DeepSeek Harness 或其他执行 Agent；
- 编写委派任务单、选择隔离工作目录；
- 续接 DeepSeek session、下发修复轮次；
- 收回执行结果并准备 Codex 审查。

### `sync`

加载 `contexts/sync.md`，当工作主要是：

- 更新 STATUS、handoff、journal；
- 生成交接、恢复新会话；
- 提交 Git、归档事项；
- 提升知识、整理索引；
- 创建新事项并登记。

## 3. 判定顺序

1. **安全门先于模式。** 出现删除、发布、部署、敏感数据、外部写入、跨事项修改或关键歧义时，先按 `01-agent-layer/AGENT_GUIDE.md` 第 6 节处理。
2. **看交付物，不只看动词。**
   - “检查并修好” = `coding` + `review` + `sync`；
   - “写文档说明这个功能” = `coding`（文档构建），不自动加载 review；
   - “看看 STATUS 是否真实” = `review` + `sync`。
3. **默认顺序。** 生产/实现上下文优先，独立检查其次，状态同步最后。用户显式指定顺序时服从用户。
4. **模式可以组合。** 加载所有已选模式的模块，不因后加载的模式丢弃先前约束。

## 4. 加载矩阵

| 输入 | 必读 | 额外加载 |
|---|---|---|
| `auto` / 未判定 | 核心 + 事项状态 + 本路由 | 先只读调查，再判定 |
| `coding` | 核心 + 事项状态 + 本路由 | `contexts/coding.md` |
| `delegation` | 核心 + 事项状态 + 本路由 | `contexts/delegation.md` |
| `review` | 核心 + 事项状态 + 本路由 | `contexts/codex-review.md` |
| `sync` | 核心 + 事项状态 + 本路由 | `contexts/sync.md` |
| `coding,review` | 以上公共部分 | coding + review |
| 委派后审查 | 以上公共部分 | delegation + review + sync |
| 恢复/压缩后 | 核心 + STATUS + handoff + 最近 journal + 本路由 | 按当前场景加载 |
| 新事项创建 | 核心 + 模板 + 本路由 | `contexts/sync.md`，再按实际工作加载 |

## 5. 重新路由触发条件

出现以下任一情况，暂停当前模式并重新判断：

- 从实现切换到验证、交接或提交；
- 用户新增会改变范围或验收标准的约束；
- 发现阻塞、错误假设或高风险副作用；
- 上下文被压缩、换 Agent、换会话；
- 进入 Git 合并、归档或发布阶段；
- 当前 handoff 与实际问题不一致。

## 6. 路由记录

在 journal 中写一行即可：

```text
Route: coding+sync — 实现 CLI，随后更新状态并提交。
```

不需要为纯只读的小问题写冗余记录，但状态发生变化时必须记录。

## 7. 歧义处理

先做安全的只读检查，再根据事实判定。仍有两种以上会改变结果的解释时，问一个决定性问题。不要因为无法路由就停止一切信息收集，也不要为了显得自主而猜测高风险范围。
