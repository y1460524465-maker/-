# Git Protocol

## 每次会话

开始时：

```text
git status --short --branch
git log --oneline --decorate -n 5
```

结束前再次检查。发现不属于当前事项的改动时，保留它们，不覆盖、不擅自提交。

## 检查点

一次提交应表达一个可验证结果，不是一段时间。建议时点：

- 一个功能/文档片段完成并通过验证；
- 一次排查得出可复现结论；
- 状态与交接进入可恢复状态；
- 事项创建、归档或知识提升。

提交信息：

```text
item(<item-id>): <结果>
workspace: <全局规范或工具结果>
```

## 暂存规则

- 明确列出本次路径或使用交互式暂存。
- 不把无关文件吞入提交。
- 提交前运行 `python 01-agent-layer/scripts/workspace.py validate`。
- 同一检查点中的代码/文档、STATUS、handoff、journal 一并提交。

## 禁止默认执行

以下动作只有在用户明确要求时执行：

- 推送远端或发布；
- 合并到共享分支；
- 强制推送、改写历史、硬重置；
- 删除分支或丢弃未提交更改。

## 并发写入

- 不同事项可以并行。
- 同一事项不同操作流应使用不同 `workspaces/<stream>/`。
- 写共享状态前重新读取文件；发现外部更改时整合而不是覆盖。
- journal 采用追加。
- Git 冲突未解决时不得继续声称状态已同步。

## 恢复

新会话恢复时结合：

1. `STATUS.md` 与 `handoff.md`；
2. 最近 journal；
3. `git log` 与 `git diff`；
4. 实际运行验证。

Git 只提供历史证据，不代替当前状态说明。
